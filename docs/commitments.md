시험은 흔한 실수를 잡는 그물이다. 시험이 통과해도 이 문서와 어긋나면 어긋난 것이다.

## 1. 말

| 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|
| 확인할 것(코드에서 본 것 · 저장소 밖에서 확인할 것 · 해당 여부부터 확인할 것) | 법을 어겼다고 단정하는 말 | 도구는 사람이 확인할 지점을 알릴 뿐이고 판단은 사람이 한다 |
| 지킨 근거 있음 | 적법하다·문제없다고 단정하는 말 | 근거를 찾았다는 사실만 말한다 |
| 해당 없음(검색으로 확인) | 검색으로 확인하지 않은 "해당 없음" | AI 가 낸 검색어를 도구가 저장소에서 다시 돌려 건수가 맞은 것에만 쓴다. 확인되지 않은 것은 "걸리지 않는 것으로 보임(확인 안 됨)"이다(2026-11-11 오너 결정) |
| 모름 | "해당 없음"으로 뭉뚱그리기 | 상한·실패로 답을 받지 못했다 |
| 코드(누가 썼든). 평가는 JS/TS 저장소에서 했다 | 특정 도구가 만든 코드용이라는 표현, 'JS/TS 전용'처럼 읽히는 표현 | 코드를 누가 썼는지는 보지 않는다. AI 검토는 저장소의 파일을 언어로 가리지 않고 읽는다(2026-11-15 오너 결정) |
| 인공지능기본법 제31조 제1항 / 제2항 | 가지조문처럼 읽히는 표기 | 제1항이 사전 고지, 제2항이 결과물 표시다 |

- 사이트는 AI 검토(review)만 보인다. 2026-11-25 오너 지시로 규칙 기반 검사(scan)를 폐기했다: 그 결과를 보이던 쪽(결과 파일 열기
  `/view`, 데모 `/demo`, 조문별 검사 기록, 정책 쪽 `/policy/<id>`)과 사례 쪽(`/cases`)을 지웠고, 실행기도 그 단계를 돌리지 않는다.
  화면·메타데이터·README 에 그 검사를 가리키는 말을 두지 않는다. CLI·모델이 쓴 글(의무 지도의 '걸리는 코드', 검토 답)은 고치지
  않고 그대로 싣는다.
- 메뉴는 최근 분석 · 조문 도감 · 구조다(2026-11-25).
- review 결과 쪽의 차례는 머리 → 요약(확인할 것 N건과 제재 단추, 회색 한 줄, 주의 문구) → 의무 체크리스트(의무 한 건이 두 줄 행,
  누르면 펼침) → 이 저장소가 하는 일 → 개인정보 흐름 → 검증 정보다(2026-11-25. 2026-11-11 의 하는 일 → 흐름 → 체크리스트를 바꿨다).
- 모든 화면에 "법률 자문이 아닙니다"가 보여야 한다(`SITE.disclaimer`, 바닥글).
- AI 검토의 확인할 것이 0이면 "법적 문제가 없다는 뜻이 아니다"를 함께 보인다(`SITE.zeroCheckIsNotClearance`. 보이는 수가 0일 때만).
- 점수, 등급, 순위, 비율, 배지를 만들지 않는다. 사람이 볼 곳의 개수만 센다.
- 과징금·과태료 예상액, "걸릴 확률", 변호사 연결을 두지 않는다(변호사법 쟁점).
- 예시 결과에는 "합성 예시"라고 밝힌다. 실제 남의 저장소 결과를 예시로 쓰지 않는다. 서비스가 사용자의 요청으로 분석한
  공개 저장소의 결과는 예시가 아니라 실제 결과로 보인다(저장소·커밋·분석 id·분석 시각을 함께). 이 사이트의 실행기가 아니라 CLI 로
  미리 돌려 넣은 기록(2026-11-25 오너 지시: Vactor0911/jobtalk @ bbfb3ab, 11/24 실행)은 미리 돌린 결과임을 밝힌다.
- 처분 사례를 화면에 싣지 않는다. 팩 작성자 메모(rationale)도 싣지 않는다(사람 결정 전까지). 의무의 제목·한 줄에 덧붙은 처분·액수
  메모도 싣지 않는다.
- 의무마다 **법에 적힌 제재**는 싣는다(2026-11-24 오너 승인). CLI 의 제재 표(고정 커밋의 `src/policyofficer/profile/sanctions.jsonl`:
  법령 원문의 벌칙·과징금·과태료 조문과 그 원문 인용)에서 온 것만 쓰고, 조문·법제처 링크·원문 인용을 함께 보인다. 무게(징역 >
  과징금 > 벌금 > 과태료 > 명령 > 없음)는 그 조문으로 정해진 것이고 AI 가 판단하지 않는다. 코드나 저장소의 점수·등급이 아니다.
  표지는 언제나 "어기면"으로 시작하고, 요약 근처에 주의 문구("법에 적힌 최대 제재입니다. 위반 판정이 아니며, 실제 부과는 위반
  사실과 규모에 따라 다릅니다.")를 한 번 둔다. 이 저장소에 얼마가 나올지(예상액)는 여전히 두지 않는다. 제재의 말(과징금·과태료·
  벌금)과 그 주의 문구는 `src/lib/duties/sanction.ts` 와 제재 표에서 온 글에만 쓴다(문구 시험이 그 밖을 막는다). 제재 표에서 온 글
  (표지 말, 제재 문구, 조건, 보충, 원문)은 법령의 말을 옮긴 것이라("위반행위와 관련한 매출액" 등) 조문 원문처럼 문구 시험에서 뺀다.

### CLI 가 이미 약속한 것 (웹도 따른다)

- **코드가 밖으로 나간다는 것을 숨기지 않는다.** AI 검토는 모델이 읽은 파일의 코드를 Anthropic API 로 보낸다(비밀값은 가리고 .env
  등은 읽지 않는다). 구조 쪽에 그렇게 적는다.
- **다 보지 못한 것을 숨기지 않는다.** 검토가 보지 못한 것(저장소 밖, 읽지 않는 파일, 판단하지 못한 의무)을 체크리스트 아래에 적는다.

## 2. 범위마다 다른 약속

### 사이트 전체

- 분석 도구·광고·외부 글꼴 같은 제3자 요청을 넣지 않는다.
- 브라우저 저장소(localStorage 등)는 쓰지 않는다.

### 분석 서비스 (방향 B, 2026-10-24 오너 결정)

- 분석 결과는 누구나 본다. 숨김 장치는 두지 않는다.
- 분석 요청에 로그인이 필요 없다. 대신 남용·비용 상한을 둔다(같은 커밋의 진행 중·최근 분석으로 보내기, 하루·동시 분석 수,
  저장소 크기, 실행 시간). 값은 `docs/direction.md` 에 적는다.
- 서버의 분석은 AI 검토다(하루 상한 안에서). 분석 대상 코드는 Anthropic API 로 나간다(공개 저장소의 코드다).
- 검사는 GitHub Actions 의 새 VM 에서 하고, 대상 저장소의 코드를 실행하지 않는다.
- 저장하는 것: 저장소·커밋·분석 id·진행 단계·시각·CLI 결과 JSON(프로필과 검토). 받은 압축 파일과 코드 전체는 저장하지
  않는다(CLI JSON 에 AI 가 인용한 줄이 들어 있을 수 있다. 공개 저장소의 줄이다).
- 화면의 코드 줄은 GitHub 의 커밋 고정 링크로 보낸다. 브라우저가 다른 사이트에 요청하지 않는다.
- 비밀값(토큰, API 키)은 서버 환경 변수와 Actions secret 에만 둔다.
- 1장의 말(단정하지 않음, 점수·등급 없음, 0건이어도 문제없다는 뜻이 아님, 법률 자문 아님)은 분석 쪽에도 그대로다.

### 학기 뒤: 비공개 저장소

- 검사는 사용자 쪽(자기 GitHub Actions)에서 돌고, 우리는 코드 없는 결과만 받는다.
- 서버 AI 는 저장소별 동의, 개인정보보호법 제26조 위탁·재위탁 동의가 갖춰진 뒤에만 한다.

## 3. 엔진과 라이선스

- Semgrep CE(LGPL-2.1)는 PyPI 의존성으로만 쓴다. 바이너리나 컨테이너 이미지에 넣어 배포하지 않는다.
- Semgrep 공식 규칙(Registry)은 쓰지 않는다. 규칙 라이선스가 재배포와 서비스 제공을 금지한다.
- 이름·로고·도메인에 Semgrep 을 쓰지 않는다. "Semgrep CE 위에서 동작"이라는 사실만 적는다.
- 유료 호스팅 전에 Semgrep 에 제휴 문의를 한다.
- 이 저장소의 라이선스는 아직 정하지 않았다(비공개 또는 FSL 후보). 공개 전에 오너가 정한다.

- 브라우저 저장소를 어디까지 쓸지(테마 같은 화면 설정만 / 전혀 안 씀).
- 팩 작성자 메모(rationale)를 화면에 실을지.
- 공개 여부와 라이선스.
